# part5-toeic-trainer

TOEIC Part 5（短文穴埋め・4択）の練習セットを作る。**1回の実行で5セット、1セットは10問**。

音声が無く、1問が1文で完結するパートなので、Part 3・Part 4 とは単位が違う。**10問1セット＝約3分20秒**（本番の目安は1問20秒）。待ち時間や移動の合間に1セット、という想定。

出力先は学習アプリのリポジトリ `data/part5/`。アプリ（GitHub Pages 上の `part5.html`）はこの JSON だけを読む。

**本番の形式をそのまま再現することが唯一の目的**である。ひねった問題や難問を作ることではない。本番で起きないことは、ここでも起こしてはならない。

**Part 3・Part 4 との違い**は4つ。音声が無い（`audio` も作らない）。1問＝1文で、前後の文脈が無い。**選択肢を見た瞬間に問題の型が決まる**のがこのパートの要で、そこを練習させる。そして1セットに10問入るため、型と正解の位置を**セットの中で散らす**必要がある。

---

## ステップ0：日付・時刻の確定（必ず最初に実行）

日付・時刻の基準は必ず **JST（日本標準時, UTC+9）** とする。

1. 最初に必ずシェルで現在時刻を取得する。**`TZ=Asia/Tokyo date` を単独で信用しない。**
   タイムゾーン情報を持たない環境では `TZ` が黙って無視され、**UTC がそのまま返る**。

   ```bash
   node -e "console.log(new Intl.DateTimeFormat('sv-SE',{timeZone:'Asia/Tokyo',dateStyle:'short',timeStyle:'short'}).format(new Date()))"
   ```

2. `id` はこの実時刻から `YYYY-MM-DD-HHMM-N` として作る。`N` は**この回の何本目か**（1〜5）。
3. 実行環境が返すキャッシュ時刻（「as of ...Z」など）を現在時刻として使ってはならない。

## ステップ1：設問の型と配分

`type` は次の8種から選ぶ。

**文法（1セットに6〜7問）**

| type | 何を問うか | 選択肢の見え方 |
|---|---|---|
| `form` | 品詞の選択 | `inform` / `information` / `informative` / `informatively` のように**同じ語幹で語尾だけ違う** |
| `verb` | 動詞の形（時制・態・主語との一致） | `ship` / `ships` / `shipped` / `will be shipped` |
| `verbal` | 準動詞（to 不定詞・動名詞・分詞） | `to reduce` / `reducing` / `reduced` / `reduce` |
| `prep` | 前置詞 | `within` / `among` / `during` / `beyond` |
| `conj` | 接続詞・接続副詞 | `although` / `despite` / `therefore` / `so that` |
| `pron` | 代名詞・関係詞 | `who` / `whose` / `which` / `whom`、`its` / `their` / `theirs` |
| `comp` | 比較・数量・冠詞 | `more efficient` / `most efficient` / `as efficient` / `efficiency` |

**語彙（1セットに3〜4問）**

| type | 何を問うか | 選択肢の見え方 |
|---|---|---|
| `vocab` | 文意に合う語の選択 | `expand` / `remind` / `submit` / `attach` のように**品詞は同じで意味が違う** |

### 1セット10問の決まり

| 項目 | 決まり |
|---|---|
| 配分 | 文法6〜7問・語彙3〜4問。合計10問 |
| 型 | `form` を2問、`vocab` を3〜4問。同じ型は**最大3問**。文法の型は3種以上使う |
| 正解の位置 | A・B・C・D が**それぞれ2問以上** |
| 並び | 型を固めない。`form` が3問続く、語彙が最後に固まる、といった並びにしない |
| 場面 | 10問が同じ話題にならないようにする（社内連絡・契約・出荷・採用・施設・販促などから散らす） |

### 5セットの決まり

`data/part5/history.json` を読み、**直近10セットで使った文法トピック**（`topics`）を確認する。
この回の5セットは、直近10セットと**同じ文法トピックを3つ以上重ねない**。同じ型でも問う中身（受動態／時制の一致／分詞構文…）を変える。

## ステップ2：1問を書く

### 文

| 項目 | 基準 |
|---|---|
| 語数 | **12〜28語**（空所を1語として数える） |
| 空所 | `-------`（ハイフン7つ）を**1文に1か所だけ**置く |
| 場面 | ビジネス（社内連絡・契約・出荷・採用・施設・販促・経理）。日常会話にしない |
| 固有名詞 | 架空のものにする。実在の企業名・製品名・人名は使わない |

```
All visitors must ------- their badges at the front desk before entering the laboratory.
```

- 文の意味が空所を埋めなくても**おおよそ取れる**ようにする。空所を埋めないと何の話かも分からない文は、本番には出ない。
- 1文に情報を詰め込みすぎない。関係詞は1文に1つまで。
- **空所の前後2〜3語で解ける問題と、文全体を読まないと解けない問題を混ぜる。** 全部が前者だと本番より易しい。

### 選択肢

- 4択。`key` は `A` `B` `C` `D`。
- **文法問題は、選択肢を縦に並べたときに型が分かる形にする**（同じ語幹で語尾だけ違う、動詞の活用が並ぶ、前置詞だけが並ぶ）。本番の受験者は選択肢を見て「これは品詞問題だ」と判断してから空所に戻る。その練習ができなくなるので、型の混ざった選択肢は作らない。
- **語彙問題は、4つとも同じ品詞・同じくらいの難度**にする。1つだけ易しい語があると消去法で解けてしまう。
- 誤答は「文法的には入るが意味が合わない」「意味は合うが形が違う」のどちらかにする。**明らかに関係のない語を混ぜない。**
- `ja` に各選択肢の短い訳を入れる（語彙問題では特に重要）。品詞問題では `（名）情報` のように品詞を添えてよい。

### 訳と解説

- `ja` は**空所を正解で埋めた状態**の文の訳。自然な日本語にする。
- `explanation` は2〜4文。**なぜその形・その語なのか**を書き、誤答のうち最も紛らわしいもの1つに必ず触れる。
  文法問題では「空所は他動詞 ------- の目的語が続くので動詞」のように、**判断の手順**を書く。
- `tip` は1〜2文。**その型の見分け方**を書く。「選択肢が同じ語幹で語尾だけ違えば品詞問題。空所の前後だけ見る」のように、次に同じ型が出たときに使える形にする。

## ステップ3：語注と Point

### glossary（語注）

- **8〜12語**。10問の文に実在する語・熟語だけ。
- キーは**本文の表層形を小文字化したもの**（`submitted`、`in charge of` など。原形に直さない）。
- 値は `{ "lemma": 原形, "pos": 品詞, "ja": 訳, "note": 補足 }`。`note` は不要なら空文字。
- **半分以上は2語以上のまとまりにする**（`in charge of`、`prior to`、`no later than`、`be subject to`）。Part 5 は語彙問題でこの形が問われる。
- 高校初級までの単語を基本の意味のまま入れない。**覚えて初めて点が動く語だけ**を選ぶ。

### point（セット全体の総括）

```json
"point": {
  "lead": "選択肢の見た目で型を決めてから、空所の前後を見る",
  "items": [
    { "title": "短い見出し", "body": "次のセットで再現できる手順として書く" }
  ]
}
```

- `lead` はこのセットを通じて身につけてほしい手順を1行で。
- `items` は2〜3項目。**設問1問に閉じた話ではなく、10問を通して使える判断の型**を書く。
  「選択肢が語尾だけ違えば品詞問題」「空所の前が前置詞なら名詞か動名詞」「接続詞と前置詞が混ざっていたら、空所のあとが文か句かを見る」のように、内容から離れても使える形にする。
- 設問1問だけに閉じた話は `tip` 側に書く。

## ステップ4：JSON の出力

### 4-1. 出力先

| 状況 | 動作 |
|---|---|
| 実行環境にアプリのリポジトリがある | `data/part5/<id>.json` を**5本**書き出し、`index.json` と `history.json` を更新してコミット＆プッシュ |
| リポジトリが無い／書き込みに失敗した | JSON を **`json` 指定のコードブロック**でセットごとに出力し、失敗した旨も必ず報告する |

**5本は1つのコミットにまとめる。** 途中で作れなくなった場合は、**できた分だけを書き出して push し、何本作れたかを報告する**。

**作業は必ず `main` ブランチに対して行う。** GitHub Pages が配信しているのは `main` だけなので、作業ブランチに置いたセットはアプリに出てこない。プルリクエストも作らない。

```bash
git checkout main
git pull --ff-only origin main
# ここで JSON を書き出す
git add data/part5
git commit -m "Part 5 追加: <日付> の5セット"
git push origin main
```

**`data/news/`・`data/part3/`・`data/part4/` には触れない。** それぞれ別ルーティンが管理している。

### 4-2. スキーマ（v1）

```json
{
  "schemaVersion": 1,
  "type": "part5",
  "id": "2026-09-20-0700-1",
  "date": "2026-09-20",
  "time": "07:00",
  "createdAt": "2026-09-20T07:00:00+09:00",
  "sample": false,
  "focus": "文法7・語彙3",
  "questions": [
    {
      "id": "q1",
      "type": "form",
      "prompt": "All visitors must ------- their badges at the front desk before entering the laboratory.",
      "choices": [
        { "key": "A", "text": "collect", "ja": "受け取る" },
        { "key": "B", "text": "collection", "ja": "（名）回収" },
        { "key": "C", "text": "collective", "ja": "（形）集団の" },
        { "key": "D", "text": "collectively", "ja": "（副）まとめて" }
      ],
      "answer": "A",
      "ja": "来訪者は全員、研究室に入る前に受付でバッジを受け取らなければならない。",
      "explanation": "日本語の解説",
      "tip": "この型の見分け方"
    }
  ],
  "glossary": {
    "prior to": { "lemma": "prior to", "pos": "熟", "ja": "〜より前に", "note": "before の硬い言い方" }
  },
  "point": {
    "lead": "...",
    "items": [{ "title": "...", "body": "..." }]
  }
}
```

**`audio` は書かない。** 設問1問ぶんずつの読み上げ音声は、GitHub Actions（`.github/workflows/part3-audio.yml`）がこのセットを main で見つけたあとに `tools/make-part5-audio.js` で作り、`audio` を足して別コミットで入れる。ここで書くと作り直しの判定が壊れる。読み上げには空所を正解で埋めた文が使われる。

### 4-3. index.json の更新

`data/part5/index.json` の `items` の**先頭**に次を挿入する。

```json
{ "id": "2026-09-20-0700-1", "no": 6, "date": "2026-09-20", "time": "07:00",
  "kind": "文法7・語彙3", "questions": 10, "file": "2026-09-20-0700-1.json" }
```

- `no` は Part 5 の通し番号。**既存項目の最大値 + 1** から順に振る（無ければ 1 から）。
- `kind` は `focus` と同じ文字列。一覧の見出しになる。
- 5本ぶんを、**1本目が小さい番号**になるように先頭へ挿入する。
- `updatedAt` を JST の実時刻に更新する。**古い項目は削除しない。**

### 4-4. history.json への追記

`data/part5/history.json` を読み（無ければ作る）、`items` の**先頭**に5件挿入する。

```json
{ "id": "2026-09-20-0700-1", "date": "2026-09-20", "focus": "文法7・語彙3",
  "types": ["form", "form", "verb", "verbal", "prep", "conj", "pron", "vocab", "vocab", "vocab"],
  "topics": ["名詞と動詞の区別", "受動態", "分詞の後置修飾", "期限の前置詞", "譲歩の接続詞", "所有格の関係詞"] }
```

- `topics` は**その回で問うた文法トピック**を日本語で並べる。次回以降の重複判定に使う。
- **古い項目は削除しない。** `updatedAt` を JST の実時刻に更新する。

初回だけ、ファイル全体はこの形にする。

```json
{ "schemaVersion": 1, "type": "part5-history", "updatedAt": "2026-09-20T07:02:00+09:00", "items": [] }
```

### 4-5. 出力前の自己検証

リポジトリがある場合は、機械の確認を必ず通す。落ちたら直してから push する。

```bash
node tools/check-part5.js --all
```

- `questions` が10問で、`id` が `q1`〜`q10`
- すべての `prompt` に `-------`（ハイフン4つ以上の並び）が**ちょうど1か所**ある
- 1文が 12〜28語
- 各設問4択で、`answer` が `choices` の `key` のいずれかと一致する
- すべての選択肢に `text` と `ja` がある
- すべての設問に `ja`（全文訳）・`explanation`・`tip` がある
- `type` が8種のいずれかで、`form` が2問、`vocab` が3〜4問、同じ型が4問以上になっていない
- 文法の型が3種以上
- 10問の正解が A・B・C・D それぞれ2問以上
- `focus` が「文法N・語彙M」の形で、実際の配分と一致している
- `glossary` が8〜12語で、全キーが本文に実在する小文字表層形である
- `glossary` の半分以上が2語以上のまとまり
- `point.lead` があり、`point.items` が2〜3項目
- `audio` を書いていない
- `index.json` に `no`・`kind`・`questions` を入れ、`index.json` と `history.json` の先頭に今回の項目を追記した

5本まとめての確認：

- 5本の `id` がすべて違う（`-1` 〜 `-5` の連番）
- 直近10セットと同じ文法トピックが3つ以上重なっていない
- 5本の `focus` が全部同じ配分になっていない

## 注意事項

- **1回5セット（50問）。** 週1回の実行で1週間ぶんを作る。5本を超えて作らない。
- **音声のことは何もしない。** Actions が別途作る。音声がまだ無いセットは端末の読み上げで鳴るので、学習は止まらない。
- 実在の企業名・製品名・人名を使わない。架空のものにする。
- 政治的・宗教的な主張、健康や金銭の助言になる内容は扱わない。
