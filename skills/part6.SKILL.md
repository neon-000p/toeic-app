# part6-toeic-trainer

TOEIC Part 6（長文穴埋め・4択）の練習セットを作る。**1回の実行で5セット、1セットは文書1本＋4問**。

本番は1つの文書に空所が4つあり、そのうち1つは**一文挿入**（文書に合う1文を選ぶ）になっている。この単位をそのまま1セットにする。1セットは2〜3分。

出力先は学習アプリのリポジトリ `data/part6/`。アプリ（GitHub Pages 上の `part6.html`）はこの JSON だけを読む。

**本番の形式をそのまま再現することが唯一の目的**である。本番で起きないことは、ここでも起こしてはならない。

**Part 5 との違い**が要になる。Part 5 は1文の中だけで答えが決まるが、**Part 6 は空所の前後の文まで読まないと決まらない問題が必ず入る**。時制も接続副詞も代名詞も、文書全体の流れで決まる。1文で閉じる問題ばかり作ると Part 5 と変わらなくなるので、**4問のうち2問以上は、空所のある文だけでは決まらない**ようにする。

---

## ステップ0：日付・時刻の確定（必ず最初に実行）

日付・時刻の基準は必ず **JST（日本標準時, UTC+9）** とする。

1. 最初に必ずシェルで現在時刻を取得する。**`TZ=Asia/Tokyo date` を単独で信用しない。**

   ```bash
   node -e "console.log(new Intl.DateTimeFormat('sv-SE',{timeZone:'Asia/Tokyo',dateStyle:'short',timeStyle:'short'}).format(new Date()))"
   ```

2. `id` はこの実時刻から `YYYY-MM-DD-HHMM-N` として作る。`N` は**この回の何本目か**（1〜5）。
3. 実行環境が返すキャッシュ時刻を現在時刻として使ってはならない。

## ステップ1：文書の種類と場面

`docType` は次の7種から選ぶ。`intro` の言い回しは種類ごとに決まっており、**勝手に変えてはならない**。

| docType | intro の言い回し | 中身の例 | 頭（header） |
|---|---|---|---|
| `email` | the following e-mail | 取引先とのやり取り、社内の連絡 | To / From / Subject / Date |
| `memo` | the following memo | 社内通達、部署への指示 | To / From / Subject / Date |
| `notice` | the following notice | 掲示、館内のお知らせ、工事案内 | 見出し1行 |
| `article` | the following article | 地域紙・業界紙の短い記事 | 見出し1行 |
| `advertisement` | the following advertisement | 店舗・サービス・求人の広告 | 見出し1行 |
| `letter` | the following letter | 採用連絡、案内状、礼状 | 日付・宛名 |
| `instructions` | the following instructions | 手順書、利用案内 | 見出し1行 |

`intro` は必ずこの形にする。

```
Questions 1-4 refer to the following <言い回し>.
```

### 選定ルール

1. `data/part6/history.json` を読み、直近10セットの `docType` と `scene` を確認する。
2. **直近10件に出た場面（`scene`）は選ばない。**
3. **この回の5セットは、5つとも別の `docType` にする。**
4. `email` と `notice` は本番で多いので、5本のうち**必ず1本ずつ入れる**。
5. `scene` は「大分類｜具体的な状況」の形で書く（例 `社内メール｜在庫システムの切り替え`）。
   Part 6 は読む問題なので、**アプリでは最初から表示する**（Part 3・Part 4 のように伏せない）。

## ステップ2：文書を書く

### 分量

| 項目 | 基準 |
|---|---|
| 段落 | 2〜4段落 |
| 1段落の文 | 2〜5文 |
| 本文の総語数 | **90〜160語**（空所を1語として数える。header は数えない） |
| 1文の語数 | 8〜30語 |

### 空所

- **本文に空所を4か所**置く。1文につき1か所まで。
- 空所は `-------`（ハイフン7つ）で書き、その文に `q` としてその空所が何番目の設問かを持たせる（1〜4）。
- **空所は文書全体に散らす。** 4つとも同じ段落に置かない。1段落目に1つ、2段落目に2つ、のように分ける。
- **一文挿入の空所は、`en` を `-------` だけにした文**として置く（その位置に1文まるごと入る）。`ja` は空文字にする。

### 書き方の制約

- 現実のビジネス文書として成り立つ具体性を持たせる（日付、金額、部署名、期限）。固有名詞は架空のものにする。
- **語彙は TOEIC 頻出語の範囲**に収める。
- **文書の流れを作る。** 用件 → 事情や理由 → 依頼や案内 → 締め。流れが無いと、接続副詞や時制の問題が作れない。
- **句動詞・熟語を3つ以上入れる**（`be in charge of`、`prior to`、`no later than`、`take effect`）。
- `ja` は1文ずつ、その文だけの自然な日本語訳にする。空所のある文は、**正解を入れた状態の訳**にする。

## ステップ3：設問を4問作る

### 型の配分

`type` は次の9種から選ぶ。

| type | 何を問うか |
|---|---|
| `sentence` | **一文挿入**（文書に合う1文を選ぶ） |
| `form` | 品詞の選択 |
| `verb` | 動詞の形（時制・態・一致） |
| `verbal` | 準動詞（to 不定詞・動名詞・分詞） |
| `prep` | 前置詞 |
| `conj` | 接続詞・**接続副詞**（however / therefore / in addition …） |
| `pron` | 代名詞・関係詞 |
| `comp` | 比較・数量 |
| `vocab` | 語彙選択 |

**1セット4問の決まり**

| 項目 | 決まり |
|---|---|
| `sentence` | **ちょうど1問。** 本番の各文書に必ず1問入る |
| 残り3問 | 文法1〜2問・語彙1〜2問。同じ型を2問入れない |
| 文脈依存 | **4問のうち2問以上**は、空所のある文だけでは決まらないようにする（`sentence` はこれに数える） |
| 正解の位置 | A・B・C・D が**同じ文字3問以上にならない**ようにする |
| 並び | `questions` は空所の順（1番目の空所が q1） |

### 一文挿入（`sentence`）の作り方

- 選択肢は**4つとも完全な文**にする。長さを揃える（8〜18語）。
- 正解は、**前の文と後ろの文の両方につながる**ものにする。前だけ、後ろだけで決まる問題は本番より易しい。
- 誤答は次の形で作る。
  - 文書の話題には合うが、その位置には合わない（時系列が前後する）
  - 文書に出ていない前提を持ち込む（まだ触れていない人や物を指す）
  - 内容は正しいが、文書の目的とずれる
- `choices[].ja` は**その文の訳**（短い語句ではなく、文として訳す）。
- `explanation` には、**前の文と後ろの文のどこにつながるか**を必ず書く。

### 文脈で決まる問題の作り方

Part 6 で本番らしさが出るのはここ。次のどれかを必ず入れる。

- **接続副詞**：前の文との関係（逆接・追加・因果）で決まる。空所の文だけ見ても選べない
- **時制**：文書の他の場所にある日付や `last week` / `starting next month` で決まる
- **代名詞・指示語**：前の文に出た人や物を受ける
- **語彙**：前後の文で言い換えられている語を選ぶ

### 選択肢（`sentence` 以外）

- 4択。`key` は `A` `B` `C` `D`。
- 文法問題は、選択肢を縦に並べたときに型が分かる形にする。
- 語彙問題は4つとも同じ品詞・同じくらいの難度にする。
- `ja` に短い訳を入れる。

## ステップ4：解説・語注・Point

- `explanation` は2〜4文。**どこを読めば決まるか**（空所の前の文、2段落目の日付、など）を必ず書き、紛らわしい誤答1つに触れる。
- `tip` は1〜2文。**その型の見分け方**を書く。
- `glossary` は**8〜12語**、キーは本文の表層形を小文字化したもの。**半分以上は2語以上のまとまり**にする。高校初級までの単語を基本の意味のまま入れない。
- 値は `{ "lemma": 原形, "pos": 品詞, "ja": 訳, "note": 補足, "example": { "en": 例文, "ja": 例文の訳 } }`。`pos` は「名／動／形／副／前／接／熟」。
- **各語に例文を1つ付ける**（時事の語彙と同じ）。`"example": { "en": 英語例文, "ja": その訳 }`。
  - **本文の文をそのまま使わない**。同じ語を、TOEIC のビジネス・日常の別の場面に置いた短い1文（8〜15語程度）を新たに作る。本文はアプリの対訳で読めるので、例文は「別の場面でも同じ意味で使える」ことを見せるためのもの。
  - 見出しの語（原形でも活用形でもよい）を必ず含め、`ja` の意味で使う。多義語は `ja` に書いた意味の例文にする。
  - `ja` は例文の自然な和訳。
- `point` は `lead`（1行）と `items` 2〜3項目。**セット全体を貫く読み方**を書く。
  「空所の文だけで決まらないときは、前の文に戻る」「一文挿入は前後の両方につながるものを選ぶ」のように、次のセットで再現できる形にする。

## ステップ5：JSON の出力

### 5-1. 出力先

| 状況 | 動作 |
|---|---|
| 実行環境にアプリのリポジトリがある | `data/part6/<id>.json` を**5本**書き出し、`index.json` と `history.json` を更新してコミット＆プッシュ |
| リポジトリが無い／書き込みに失敗した | JSON を **`json` 指定のコードブロック**でセットごとに出力し、失敗した旨も必ず報告する |

**作業は必ず `main` ブランチに対して行う。** プルリクエストは作らない。5本を1つのコミットにまとめ、メッセージは `Part 6 追加: <日付> の5セット`。

**`data/news/`・`data/part3/`・`data/part4/`・`data/part5/` には触れない。**

### 5-2. スキーマ（v1）

```json
{
  "schemaVersion": 1,
  "type": "part6",
  "id": "2026-09-20-0800-1",
  "date": "2026-09-20",
  "time": "08:00",
  "createdAt": "2026-09-20T08:00:00+09:00",
  "sample": false,
  "docType": "email",
  "scene": "社内メール｜在庫システムの切り替え",
  "intro": "Questions 1-4 refer to the following e-mail.",
  "header": [
    { "label": "To", "text": "All Warehouse Staff" },
    { "label": "From", "text": "Dana Whitfield, Operations" },
    { "label": "Subject", "text": "New inventory system" }
  ],
  "paragraphs": [
    {
      "sentences": [
        { "en": "Starting on 1 October, we will ------- to a new inventory system.", "ja": "10月1日より、新しい在庫システムに切り替えます。", "q": 1 },
        { "en": "The current system will be shut down at the end of September.", "ja": "現在のシステムは9月末で停止します。" }
      ]
    }
  ],
  "questions": [
    {
      "id": "q1",
      "type": "verb",
      "choices": [
        { "key": "A", "text": "switch", "ja": "切り替える" },
        { "key": "B", "text": "switched", "ja": "切り替えた" },
        { "key": "C", "text": "switching", "ja": "切り替えている" },
        { "key": "D", "text": "to switch", "ja": "切り替えるため" }
      ],
      "answer": "A",
      "explanation": "日本語の解説",
      "tip": "この型の見分け方"
    }
  ],
  "glossary": {
    "take effect": { "lemma": "take effect", "pos": "熟", "ja": "実施される、効力が生じる", "note": "",
                     "example": { "en": "The new parking rules will take effect next Monday.", "ja": "新しい駐車規則は来週の月曜日から実施される。" } }
  },
  "point": {
    "lead": "空所の文で決まらなければ、前の文に戻る",
    "items": [ { "title": "...", "body": "..." } ]
  }
}
```

**`audio` は書かない。** Part 6 は読む問題なので音声ファイルは持たない。アプリの対訳ステップでは端末（Chrome / Edge）の読み上げで鳴らす。

### 5-3. index.json の更新

```json
{ "id": "2026-09-20-0800-1", "no": 6, "date": "2026-09-20", "time": "08:00",
  "docType": "email", "kind": "メール", "questions": 4, "file": "2026-09-20-0800-1.json" }
```

`no` は既存の最大値 + 1 から順に振る。`kind` は種類の日本語（メール／社内連絡／掲示／記事／広告／手紙／説明書）。`updatedAt` を JST の実時刻に更新し、**古い項目は削除しない。**

### 5-4. history.json への追記

```json
{ "id": "2026-09-20-0800-1", "date": "2026-09-20", "scene": "社内メール｜在庫システムの切り替え",
  "docType": "email", "types": ["verb", "conj", "vocab", "sentence"] }
```

**古い項目は削除しない。** `updatedAt` を更新する。初回だけ、ファイル全体はこの形にする。

```json
{ "schemaVersion": 1, "type": "part6-history", "updatedAt": "2026-09-20T08:02:00+09:00", "items": [] }
```

### 5-5. 出力前の自己検証

```bash
node tools/check-part6.js --all
```

- `docType` が7種のいずれかで、`intro` がその言い回しと一致している
- `paragraphs` が2〜4段落、各段落2〜5文、本文の総語数が 90〜160語
- 本文の空所がちょうど4か所で、`q` が 1〜4 を1つずつ指している
- `questions` が4問、`type` が9種のいずれか、`sentence` がちょうど1問、同じ型が2問無い
- 一文挿入の空所は、`en` が `-------` だけの文になっている
- 各設問4択で、`answer` が `choices` の `key` のいずれかと一致する
- すべての選択肢に `text` と `ja` がある。`sentence` の選択肢は4つとも完全な文（8〜18語）
- 4問の正解に同じ文字が3問以上無い
- 空所のある文以外の `sentences` に `ja` がある
- `glossary` が8〜12語で、全キーが本文に実在する小文字表層形。半分以上が2語以上のまとまり
- `glossary` の全語に `example`（`en` と `ja`）があり、どれも本文の文をそのまま写していない
- `point.lead` があり、`point.items` が2〜3項目
- `audio` を書いていない
- `index.json` に `no`・`kind`・`questions` を入れ、`index.json` と `history.json` の先頭に今回の項目を追記した

5本まとめての確認：

- 5本の `docType` と `scene` がすべて違う
- `email` と `notice` が1本ずつ入っている
- 5本の `id` がすべて違う（`-1` 〜 `-5` の連番）

## 注意事項

- **1回5セット。** 週1回の実行で1週間ぶんを作る。
- **音声のことは何もしない。** Part 6 は音声ファイルを持たず、端末の読み上げで鳴らす。
- 実在の企業名・製品名・人名を使わない。架空のものにする。
- 政治的・宗教的な主張、健康や金銭の助言になる内容は扱わない。
